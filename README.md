# ticket-doctor:Bug 工单自动预检 Agent

面向研发协作场景的工单预检服务:Bug 提交时自动完成一轮诊断,开发接手时拿到的是带证据的根因假设,而不是一张空白工单。

## 功能

- **自动预检**:工单提交后,Agent 自动读取问题上下文,按需检索日志、在运行开始时解析并钉死的 Git commit 上搜索和读取代码,还可通过受约束的浏览器复现(执行器已就绪,Playwright 驱动与业务测试环境待接入)执行业务断言,产出结构化的根因假设与下一步建议。
- **证据可核验**:工具执行时由系统签发证据 ID,报告只引用 ID;程序校验引用存在性、运行归属与版本一致性;区分"异常已复现、候选原因、根因已验证",证据不足时强制降级并附待验证项,材料不足输出 `partial` 与缺失清单。
- **运行治理**:幂等受理按 (工单, requestKey) 原子 claim,每次运行有独立 runId(同工单可做新旧 Skill 对照);模型循环有最大迭代、工具调用次数、总超时与无进展保护;工具失败留痕;任何路径都保证唯一终态。
- **独立审计与定向回流**:报告经独立审计 Agent 对抗式检查(复现有效性、归因充分性),三档结论(pass/degrade/reject);未通过时程序按问题类型定向回流(补证/假设修订),带失败反馈重跑,回流预算、同维度熔断与 token 预算控制循环;降级交付保留已核实结论与待验证项。
- **Skill 版本固定**:诊断方法论按目录版本化(sha256 内容哈希),运行开始选定并记录 skill_selected 事件,可追溯"当时用的是哪一版"。
- **全程审计**:每次诊断以 append-only JSONL 记录完整事件(模型决策、工具调用、观察、用量),进度和报告都从事件投影,可完整回放。
- **接入面**:本地 HTTP API(提交/进度/事件/备注文本);飞书群机器人长连接受理 @ 消息,异步诊断后回复报告,无需公网地址。

## 设计目的

把开发接手后才做的"先让 AI 看一遍"提前到提单时刻,填补"测试提单 → 开发响应"之间的等待空白;不替代人工判断,只做材料收集与第一轮排查。诊断核心与外部依赖解耦:模型引擎、日志源、代码源都收在端口接口后面,换日志平台或模型不需要改领域逻辑;诊断结果先进事件日志再投递,回写失败重试投递即可,不重复调用模型。

## 启动

```bash
npm install
npm run doctor:demo        # 零模型成本演示(Fake Engine)
DEEPSEEK_API_KEY=sk-xxx npm run doctor:real   # 真实模型诊断演示
npm run doctor:server      # 本地 HTTP 服务(:7777),POST /api/tickets 提交工单
```
