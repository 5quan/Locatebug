# ticket-doctor:Bug 工单自动预检 Agent

面向研发协作场景的工单预检服务:Bug 提交时自动完成一轮诊断,开发接手时拿到的是带证据的根因假设,而不是一张空白工单。

## 功能

- **自动预检**:工单提交后,Agent 自动读取问题上下文,按服务与时间窗检索日志,在工单指定的 Git commit 上搜索和读取代码,产出结构化的根因假设与下一步建议。
- **证据可核验**:模型引用的日志/代码片段必须与真实工具查询结果交叉命中,未命中标记 `unverified` 并强制降为低置信度;材料不足时输出 `partial` 与缺失清单,不伪装成完整诊断。
- **运行治理**:同工单幂等受理(并发/重启不重复诊断);模型循环有最大迭代、工具调用次数、总超时与无进展保护;任何路径都保证唯一终态。
- **全程审计**:每次诊断以 append-only JSONL 记录完整事件(模型决策、工具调用、观察、用量),进度和报告都从事件投影,可完整回放。
- **接入面**:本地 HTTP API(提交/进度/事件/备注文本);飞书群机器人长连接受理 @ 消息,异步诊断后回复报告,无需公网地址。

## 设计目的

把开发接手后才做的"先让 AI 看一遍"提前到提单时刻,填补"测试提单 → 开发响应"之间的等待空白;不替代人工判断,只做材料收集与第一轮排查。诊断核心与外部依赖解耦:模型引擎、日志源、代码源都收在端口接口后面,换日志平台或模型不需要改领域逻辑;诊断结果先进事件日志再投递,回写失败重试投递即可,不重复调用模型。

## 启动

```bash
npm install
npm run doctor:demo        # 零模型成本演示(Fake Engine)
DEEPSEEK_API_KEY=sk-xxx npm run doctor:real   # 真实模型诊断演示
npm run doctor:server      # 本地 HTTP 服务(:7777),POST /api/tickets 提交工单
```
